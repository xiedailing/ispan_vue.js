# note 筆記應用程式 — 教學指南（備課用，不發給學生）

> 這份指南是給老師自己看的，用來搭配《Vue3的基礎與應用.pdf》最後一章的「筆記本應用程式」上課。
> 目標班級：UI/UX 班，學生學過 JS 但邏輯理解偏弱、對畫面美感敏感。

## 這次重寫跟舊版簡報畫面對不上的地方

上課對照簡報畫面時，記得口頭提醒學生這幾點差異（簡報截圖還是舊的 Bootstrap 版面）：

1. **外觀骨架是純 CSS 手寫的「便利貼佈告欄」風格**（彩色卡片、輕微旋轉、hover 浮起），**icon 則改用 Font Awesome、並掛載 Bootstrap 5**——兩者都是在 [index.html](index.html) 用 CDN `<link>`/`<script>` 掛載，沒有用 npm 安裝，所以 `package.json` 裡看不到它們。程式邏輯沒變，只是圖示跟前一版純 emoji 的畫面不一樣。
2. **新增/編輯合成同一個元件**：[NoteEditor.vue](src/components/NoteEditor.vue) 同時處理「新增」跟「編輯」，畫面上不放「新增筆記」「編輯筆記」這種標題文字，走 Notion 那種「打開就是標題+內文，沒有多餘框線」的簡潔感。
3. **拿掉「儲存」按鈕**：新增/編輯筆記不用按按鈕，打字的時候就即時存到 Pinia store 裡（`watch` 監看輸入內容）。
4. **刪除筆記的確認彈窗**：不用 Bootstrap Modal，改成自己寫的簡單彈窗（一個 `ref` 存「要刪除的那筆筆記」，有值就顯示彈窗）——這是刻意的教學安排，讓學生體會「不靠外部元件、純用 Vue 的 state 也能做出彈窗」，之後想额外示範 Bootstrap 的 `data-bs-toggle="modal"` 寫法可以當延伸教材。
5. **修正一個舊版 bug**：舊版的 `editNote` 動作寫錯變數（改到不存在的 `notes.title`），現在已經修好。

### 1. 專案建立與整體架構

對應簡報：「筆記本應用程式」「組件結構」頁。

**上課步驟**
1. 用 `npm create vite@latest` 帶學生從零建立 note 專案（或直接開已建好的專案講結構）
2. 打開 [index.html](index.html)，順手提一下 Bootstrap 5 / Font Awesome 是用 CDN `<link>` 掛進來的，跟平常「npm install 套件」的方式不一樣——這裡只是要拿圖示用，不用額外裝套件、講 build 設定
3. 打開 [App.vue](src/App.vue)，講整體版面：header（ToolBar）+ 側欄（NoteList）+ 主內容（`router-view`）
4. 指出 `<router-view>` 就是「畫面會依網址不同而替換的區塊」
5. 順手講一下 `<transition name="fade">` 讓切換頁面有淡入淡出效果，以及 `:key="$route.fullPath"` 為什麼要加（網址參數變了但元件類型沒變時，強制重新建立元件，避免畫面資料沒更新）

**常見卡點提醒**：學生容易搞混「元件」跟「頁面」——強調 ToolBar、NoteList 是固定不變的元件，只有 `router-view` 裡的內容會變。

**視覺重點**：可以順口提一下 `App.vue` 用 flex 排版做出側欄+主內容的兩欄版面，呼應他們熟悉的排版概念。

### 2. Pinia store 設計

對應簡報：各段共用的資料來源，講解時可以先獨立講完 store 再進元件。

**上課步驟**
1. 打開 [NoteStore.js](src/stores/NoteStore.js)，先看 `state` 裡的假資料陣列（5 筆筆記，每筆有 id/title/content/pinned）
2. 講 `getters`：`allNotes`/`pinnedNotes` 只是把 `notes` 篩選一遍，`visibleNotes` 是額外加的保護（濾掉還沒打標題的空白筆記）
3. 講 `actions`：`addNote`、`editNote`、`deleteNote`、`markedPinned` 分別對應四個操作
4. 強調 `addNote` 會 `return newNote`——這是第 5 章「即時儲存」能運作的關鍵

**常見卡點提醒**：getter 為什麼不用括號傳參數？可以類比成「電腦運算好、隨時可以拿來用的計算結果」，跟 actions（要主動呼叫才會執行）做對比。

### 3. Router 設置與頁面切換

對應簡報：「載入筆記」及各功能流程圖裡「跳轉到 XX 頁」的箭頭。

**上課步驟**
1. 打開 [router.js](src/router.js)，對照四個路徑：`/`、`/add`、`/edit/:id`、`/search`
2. 指出 `/add` 跟 `/edit/:id` 兩條路徑指向**同一個元件** [NoteEditor.vue](src/components/NoteEditor.vue)——先預告第 5 章會講元件裡怎麼判斷「現在是新增還是編輯」
3. 指出 `/edit/:id` 的 `:id` 是「網址帶資料」的寫法
4. 回到 [NoteList.vue](src/components/NoteList.vue)，看 `<router-link :to="{ name: 'edit', params: { id: note.id } }">` 怎麼把某一筆筆記的 id 塞進網址
5. 現場點一筆筆記，開瀏覽器網址列，讓學生親眼看到網址變成 `/edit/1` 這種格式

**常見卡點提醒**：這是本章最重要也最容易卡住的地方——「資料怎麼從清單頁傳到編輯頁」。建議放慢速度，搭配網址列實際變化來講，比純講程式碼有效。

### 4. 筆記清單與筆記牆

對應簡報：「功能流程說明-筆記清單」。

**上課步驟**
1. 打開 [NoteList.vue](src/components/NoteList.vue)，看 `v-for="note in noteStore.pinnedNotes"` 跟 `allNotes` 兩段幾乎一樣的清單
2. 打開 [NoteGrid.vue](src/components/NoteGrid.vue)，看 `v-for="(note, index) in noteStore.visibleNotes"`——這裡多了 `index`
3. 講 `getColor(index)` / `getRotation(index)` 怎麼靠 `index % 陣列長度` 讓卡片顏色跟角度輪流變化
4. 現場改一下 `colors` 或 `rotations` 陣列的數值，讓學生看到畫面即時變化

**常見卡點提醒**：`index % colors.length` 這個「餘數輪流套用」的技巧對邏輯弱的學生可能第一次看到，建議畫一個簡單的表格（index 0,1,2,3,4,5... 對應到顏色 0,1,2,3,4,0...）幫助理解。

**視覺重點**：這段是這次重寫的美術亮點，可以多花時間讓學生體會「同一份資料，用 index 稍微變化樣式，就能做出便利貼隨性感」。

### 5. 新增/編輯筆記（合成一個元件、即時儲存）

對應簡報：「功能流程說明-新增筆記」「功能流程說明-編輯筆記」。

**上課步驟**
1. 打開 [NoteEditor.vue](src/components/NoteEditor.vue)，先看第一行邏輯：
   ```js
   const noteId = route.params.id ? Number(route.params.id) : noteStore.addNote('', '').id
   ```
   講清楚這行在做什麼判斷——網址有帶 `id`（`/edit/1`）就是編輯既有筆記；沒帶 `id`（`/add`）就馬上呼叫 `noteStore.addNote('', '')` 建立一筆空白筆記，然後把新筆記的 `id` 當作接下來要編輯的對象
2. 強調畫面上刻意不放「新增筆記」「編輯筆記」這種標題字——只有一個大大的標題輸入框跟內容輸入框，就像 Notion 打開一頁筆記那樣直接
3. 講 `watch([title, content], () => {...})`：只要標題或內容改變，就自動呼叫 `editNote` 把資料寫回 store
4. 現場打字示範，指出畫面右上角「已儲存」的提示怎麼出現又消失（`setTimeout` 控制）
5. 延伸提問：如果進新增頁但什麼都沒打就離開，store 裡會多一筆空白筆記——問學生「這樣好嗎？要怎麼解決？」（可以當課後思考題，不用當堂解答）

**常見卡點提醒**：這段的核心觀念是「新增其實就是先建立一筆空白資料，再持續編輯它，跟編輯共用同一套邏輯」，跟學生強調這點可以省去很多疑惑。`watch` 的觸發時機（打字時、不是按下什麼按鈕時）也建議多示範幾次。

## 課程結尾複習清單

念給學生聽，收斂這個專案示範到的核心概念：

- **資料傳遞**：透過 `route params`（網址帶 id）把「要編輯哪一筆」從清單頁傳到編輯頁
- **Pinia**：state（資料）、getters（篩選好的資料）、actions（改資料的方法）三件事分工
- **路由**：不同網址對應不同畫面，`<router-view>` 是畫面替換的窗口；也可以讓不同網址共用同一個元件（`/add` 跟 `/edit/:id` 都用 `NoteEditor`）
- **組件拆分**：一個功能拆成 ToolBar / NoteList / NoteGrid / NoteEditor / SearchNote 各司其職

## 延伸功能：筆記內的待辦清單（多個 checkbox 項目）

每一則筆記底下可以有多個待辦項目（像 Notion 的 to-do list block），勾選會有刪除線。設計上把「新增/勾選/刪除項目」都收在 [NoteEditor.vue](src/components/NoteEditor.vue) 裡，便利貼牆上的卡片只顯示「已完成 2/5」這種摘要徽章，不放可以互動的 checkbox——這樣互動只集中在一個地方，教起來不用額外處理「卡片本身是連結，裡面的 checkbox 要擋住點擊事件」這種細節。

- `NoteStore.js`：每筆筆記多一個 `items` 陣列，每個項目是 `{ text, done }`；新增三個 action：
  - `addItem(noteId, text)`：把新項目 push 進該筆筆記的 `items`
  - `toggleItem(noteId, itemIndex)`：用索引找到項目，把 `done` 反過來
  - `removeItem(noteId, itemIndex)`：用索引 `splice` 刪掉項目
- `NoteEditor.vue`：內容欄位下方多一個「待辦項目」區塊——`v-for` 渲染現有項目（checkbox + 文字 + 刪除按鈕），底下一個輸入框，按 Enter 呼叫 `addItem`。
- `NoteGrid.vue`：卡片內容下方，如果 `note.items.length > 0`，顯示一個「✅ 已完成數/總數」的小徽章。

**上課排法建議**：放在第 5 節「新增/編輯筆記」之後，當一段獨立的小節上（不是隨堂練習，份量比單純的布林開關大一些）：
1. 先講 `items` 這個「陣列裡面每個元素又是一個物件」的資料結構，跟前面 `notes` 陣列類比
2. 講 `addItem` 怎麼 `push`、`toggleItem`/`removeItem` 怎麼用**索引**操作陣列（`splice`、直接用中括號取值改屬性）
3. 現場示範：新增幾個項目、勾選、刪除，對照畫面即時變化
4. 提醒學生：這裡選擇「只在編輯頁能改」是刻意簡化的設計決定，如果要讓便利貼牆上也能直接勾選，需要額外處理「阻止卡片連結被點擊」的技巧（`@click.stop`），可以當作課後延伸挑戰，不在課堂上教

時間成本抓 30–40 分鐘（含現場練習跟提問），比單純加一個布林值大一些，但因為都收在 `NoteEditor.vue` 一個檔案裡，不會牽動其他章節的教學順序。若整體進度吃緊，這段可以整個跳過，程式本身已經是能動的完整功能。
